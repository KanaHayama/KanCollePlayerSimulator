# KCPS 配置

依据已核实的任务条件和用户当前账号数据，生成可加载的配置文件，或修复用户指定的现有配置。遵循用户明确的范围和偏好。

## 路径与运行环境

- `<SKILL_ROOT>`：本文件所在目录。规则在 `references/`，可执行工具在 `scripts/`，可复制的模板在 `assets/templates/`。脚本内部的 `data/` 是配套公共规则数据。
- `<WORKSPACE_ROOT>`：用户为本次任务明确选定的工作区，可位于 Skill 之外的任意位置。最终配置保存到用户指定的路径；需要工具默认运行资料目录时，在明确选定的工作区下使用 `.work/`。
- 使用 PowerShell 7。使用涉及 Python 或 Node.js 的工具前，按对应工具说明确认运行环境。实时检查需要用户已运行 KCPS 和 poi 终端插件，并通过已配置的接口读取本次所需数据。
- 在运行工具的进程中设置工作区：

```powershell
$SKILL_ROOT = '<SKILL_ROOT>'
$WORKSPACE_ROOT = '<WORKSPACE_ROOT>'
$env:KCPS_WORKSPACE = $WORKSPACE_ROOT
# 如果设置文件位于其他位置，可另设 KCPS_SETTINGS_PATH。
# 连接设置默认读取工作区 .work/kcps.local.json。
```

连接与工具用法见 [API 工具说明](scripts/poi-kcps-api/README.md)。设置文件由显式参数、`KCPS_SETTINGS_PATH` 或已明确指定工作区中的 `.work/kcps.local.json` 提供；未指定时不搜索周边目录。文件输出必须有显式路径，或有通过 `KCPS_WORKSPACE`、显式设置文件中的 `WorkspaceRoot` 指定的工作区。

## 按任务选择规则

先读 [公共规则](references/公共规则.md) 和 [命名规则](references/命名规则.md)，再按任务实际完成条件读取下表中对应文件。不要一次加载所有专用规则。

| 用户任务 | 必读规则与资源 |
| --- | --- |
| 通常海域出击任务 | [出击规则](references/通常出击配置.md)；需要结构骨架时参考 [通常出击模板](assets/templates/通常出击.conf.json) |
| 期间限定活动海域、贴条、联合或游击舰队 | [活动海域规则](references/活动海域出击配置.md)；按舰队类型选择其中链接的活动模板；涉及候选优化和达成率分析时再读 [活动分析](references/活动出击达成率分析.md) |
| 演习任务 | [演习规则](references/演习配置.md) |
| 只要求组成指定舰队的任务 | [编成规则](references/编成配置.md) |
| 远征规划或远征链 | [远征规则](references/远征配置.md)；任务、远征条件、舰队和步骤由本次计划提供 |

按实际行动和海域分类：任务有期限并不意味着它使用活动海域；不能仅凭“期间限定”字样选择活动海域规则。工厂等尚无对应流程的任务不能套用出击总控，也不要承诺本 Skill 已支持。

## 执行顺序

1. 确认任务类型、目标目录和必要输入。任务编号由当前游戏 API 核对；条件、频次和路线按对应规则查证。路线、阶段和航程证据按 [运行时计划与证据](references/运行时计划与证据.md) 准备。缺少必要数据时说明缺项，不虚构账号、任务编号或可运行配置，也不代入历史任务的默认值。
2. 按需要读取用户当前舰船、装备、任务和占用状态。只读接口查询用于规划；生成配置本身不代表用户授权启动配置或改变游戏状态。
3. 按专用规则组织配置、执行单元和关联。同一出击任务包含多个海域时，明确推进顺序并按出击规则建立完成后接续；独立启动必须是明确的执行安排。模板只是结构骨架，复制到私人工作区后填充；生成新 GUID 并同步引用，不直接覆盖模板。
4. 运行对应类型的收尾和校验，再运行 `-CheckOnly` 确认无待修正项。明确区分离线结构通过与当前账号、任务、路线验证通过。远征按其工具说明单独核对，不套用出击收尾。
5. 交付配置路径、任务覆盖范围、验证结果与必要的使用条件。仅修改用户授权的文件，不自动整理其他历史配置。
