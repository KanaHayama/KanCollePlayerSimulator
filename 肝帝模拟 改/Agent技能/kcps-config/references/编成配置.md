# KCPS 编成任务配置

用这份规则指导 Agent 生成、修复或审计可直接加载的 KCPS 编成任务 `.conf.json`。

开始前必须阅读 [公共规则.md](公共规则.md) 和 [命名规则.md](命名规则.md)。任务实际要求出击时改用 [通常出击配置.md](通常出击配置.md)，要求演习时改用 [演习配置.md](演习配置.md)；三者共用 `../scripts/poi-kcps-api` 工具。

## 先判断任务类型

编成任务的完成条件只要求组成指定舰队，不要求演习、出击、远征、工厂操作或装备废弃。

- 任务说明出现“编成”“配備”并不自动代表纯编成任务。必须读完整详情，确认后面没有“同艦隊で演習”“出撃”“遠征”等动作。
- 标题中含“特務編成”也不能只凭标题分类；以游戏 API 详情和日文 wikiwiki 的当前任务页交叉确认。
- 纯编成任务通常属于编成分类，但分类值只能作为辅助证据，不能替代详情。
- 若仍无法判断，停止生成并向用户确认，不得借用演习或出击总控试跑。

## 编成输出差异

- 种类固定为中文 `编成`；文件名为 `<JST_YYYYMMDD> <频次> 编成 <任务名>.conf.json`，配置名为 `<频次> 编成 <任务名>`。
- 一个纯编成任务只建立一个配置，不加入海域或演习后缀。
- 其余输出位置、JST、频次证据、文件卫生和术语遵守公共规则。

## 确认任务 ID 和条件

先按公共规则确认游戏 `api_no`、频次、标题和当前详情，再用日文 wikiwiki 核对指定船、数量、旗舰/位置限制、舰队编号及允许的改装后形态。ID 无法确认时拒绝生成；条件或频次不确定时按公共规则记录证据和命名。

## 调查账号中的船

- 查询所有满足任务名单的实例 ID、当前改装形态、所在舰队、远征和入渠状态。
- 判断改二、改三、最终改装、名称变化形态是否仍计入原船谱系；不确定时查日文 wikiwiki 或游戏数据，不凭名称相似猜测。
- 任务要求“从名单中至少 N 艘”时，若账号允许，可使用超过最低数量的名单内船，减少自由位或谱系判定歧义。
- 任务有旗舰、随伴或位置限制时按原文固定位置；没有限制时优先采用容易识别和复核的顺序。
- 编成任务不检查士气、火力或装备，不要为了“看起来完整”加入改装、补给或入渠执行单元。

## 配置结构

纯编成任务只包含三个执行单元，顺序固定：

1. `说明`：`MemoWorkflow`
2. `接任务`：`BasicAcceptQuestWorkflow`
3. `编成`：`BasicOrganizeFleetWorkflow`

不得加入：

- `RelationalExerciseWorkflow` 或任何演习策略。
- `RelationalSortieWorkflow`、`SimpleSortieWorkflow`、路线、地图点、阵型、陆航。
- 远征、改装、补给、入渠、捞出、扔桶、通知通关或跨配置消息。
- 只起装饰作用的空总控、收尾或任务名配置。

KCPS目前没有经过验证的纯编成任务一键总控。默认由用户先触发 `接任务`，成功后再触发 `编成`；不要用演习或出击总控伪造一键流程。

执行单元通用字段、GUID、Memo 和触发设置遵守公共规则；本配置三个执行单元的 `EnableOnLoad = false`。

## 编成字段

- 默认使用 `BasicOrganizeFleetWorkflow`，明确写出目标舰队和每个位置。
- 每个位置的 `Selections` 与 `SelectShipArgs` 都必须是数组，候选 ID 集合必须一致。
- 固定船使用真实实例 ID，不只写舰种或名称。
- 同一位置需要多个等价候选时，先确认任务按船谱系而非具体实例判断，再沿用已验证的候选逻辑；纯编成任务一般不需要士气轮换。
- 不允许同一艘船出现在两个位置。
- 若船正在远征，不能生成一个假定可立即调入的配置；在 `说明` 写明需要等待或选择其他实例。
- 若固定船正在入渠，先由用户处理入渠状态；不要把出击配置的捞出流程自动套入纯编成任务。

## 说明执行单元

`说明`必须位于最前，并至少写明：

- 公共规则要求的任务、频次、来源、船和流程信息。
- 确认后的纯编成条件。
- 每个位置使用的船及其任务资格。
- 为什么使用最低数量或更多名单内船。
- 是否有船位于其他舰队、远征或入渠。
- 执行顺序：先接任务，后编成。
- 明确说明任务不检查装备，因此配置不会改装。

## JSON 与交付检查

先满足公共 JSON 数组与幂等规则；编成还要重点检查每个位置的 `Positions`、`Selections`、`SelectShipArgs` 数组彼此一致。

生成后使用共用收尾脚本：

```powershell
pwsh -ExecutionPolicy Bypass -File (Join-Path $SKILL_ROOT 'scripts\poi-kcps-api\validate\KCPS-FinalizeFormationConfig.ps1') -Path '<CONFIG_PATH>'
pwsh -ExecutionPolicy Bypass -File (Join-Path $SKILL_ROOT 'scripts\poi-kcps-api\validate\KCPS-FinalizeFormationConfig.ps1') -Path '<CONFIG_PATH>' -CheckOnly
```

交付必须满足：

- 第二次 `-CheckOnly` 的 `Ready = true`、`PendingChangeCount = 0`。
- 通用配置、任务 ID和编成专用问题数均为 0。
- 只包含说明、接任务、编成三个执行单元。
- 没有载入时启用或启用时立即触发。
- 每个位置均有候选，`Selections` 与 `SelectShipArgs` 一致，候选船确实满足任务条件。
- 文件卫生符合公共规则。
