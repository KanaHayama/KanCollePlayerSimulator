# 普通海域任务接续

用于同一配置文件内，按顺序完成多个普通海域的 Boss 战评级次数目标。先按 [通常出击配置](通常出击配置.md) 完成各图编成、配装、路线和停止条件，再按本次接续计划确定顺序。

## 完成与停止

用户手动触发第一图总控；取得规定次数的 Boss 战评级后，下一图才自动启动。未达标时因循环上限等条件停止，不推进下一图；手动中断也不能代替目标达成。若同一轮确实达标且触及循环上限，仍可确认本图已完成。停止条件按本次任务设置，容量条件遵循通常出击规则；接续工具保留明确设置的停止条件，不通过移除上限来规避误接续。

流程分为三个职责：本图总控提供结束时的统计快照，独立的 `出击完成` 执行单元判断目标并发送完成消息，下一图总控只监听该消息。完成判定不得放进下一图的触发条件。

KCPS 在 `OnAutoStop()` 前更新原生 Boss 战评级计数，在 `OnAutoStopped()` 前清空该计数。总控脚本只在清零前复制原生统计和本轮标识，停止后消费并清除快照，发送内部结果事件；不直接发送 `Clear`，也不替代原生停止判定。每次实际新启动、启用及禁用时清除遗留快照。

`出击完成` 使用 `SimpleRaiseUserEventWorkflow`，通过自己的 `OnEvent` 验证内部结果的来源、本轮标识、评级与累计次数，达标且未处理过才触发，发送其 `Message` 字段中的 `Clear`。它须保持启用监听，不能放入任何原生“直接触发”关联列表：这些关联会绕过 `OnEvent`，无法用触发条件保护消息。也不能仅以 `SortieFinishedEvent` 判断完成，它只表示一次正常回港，且总控尚未收尾。

后续总控只接收上一阶段的精确完成消息，并在正在执行或运行时忽略该启动请求。总控的 `ReturnRoomAtLast` 设为 `false`，避免前一图发送完成消息后再插入返回提督室操作，干扰下一图。

每阶段启动都会重新进入首轮。若总控启用了旗舰或舰队士气恢复等待，设置 `DoNotSleepAtFirstLoop=false`，否则 KCPS 会在本阶段首轮跳过这些等待。自然恢复目标须符合出击规则，出击时仍检查士气。该等待检查编成前的当前舰队，不能替代对新编入舰船的状态核对和失败重试。

## 接续计划

将本次计划保存到显式指定的工作路径，通过 `-PlanPath` 传入。计划是 JSON 对象：

| 字段 | 含义 |
| --- | --- |
| `Version` | `1` |
| `ChainId` | 本次稳定链标识；任务使用已核实的任务 ID 字符串，不从显示名称推断 |
| `QuestId` | 可选的游戏任务 ID；省略时仅在各阶段有唯一共同精确任务选择器时推断，无任务攻略为 `null` |
| `Stages` | 至少两个阶段，数组顺序就是执行顺序 |
| `Stages[].GroupName` | 文件内已有配置的完整名称，必须唯一匹配 |
| `Stages[].Stage` | 本链内唯一的海域及阶段标识，写入完成消息 |
| `Stages[].Condition.Type` | 当前工具仅支持 `BossRank` |
| `Stages[].Condition.Rank` | 所需评级，例如 `A`、`S` |
| `Stages[].Condition.Count` | 所需次数，正整数 |

每阶段原生 `StopIfBossBattleRankHigherOrEqualThanFlag` 必须已启用，评级和次数必须与计划相同。工具核对这些字段，不替调用者更改任务目标。完成消息为 `ChainId Stage Clear`。

```powershell
& (Join-Path $SKILL_ROOT 'scripts/poi-kcps-api/enable/KCPS-EnableSortieChain.ps1') -Path '<CONFIG_PATH>' -PlanPath '<CHAIN_PLAN_PATH>' -CheckOnly
& (Join-Path $SKILL_ROOT 'scripts/poi-kcps-api/enable/KCPS-EnableSortieChain.ps1') -Path '<CONFIG_PATH>' -PlanPath '<CHAIN_PLAN_PATH>'
```

工具给各阶段总控安装统计转发脚本，在末尾添加或填充一个 `出击完成` 通知单元，并为它生成独立的完成触发条件。总控和通知均设置 `EnableOnLoad=true`、`TriggerOnEnabled=false`、`EnableScript=true`，总控另设 `ReturnRoomAtLast=false`。普通模板提供的空白通知骨架在填写前保持禁用；生成单图且不需要对外发送完成消息时移除该骨架。保留编成、配装、出击策略及停止后的入渠清理引用。

已有未知脚本或可能冲突的关联需要先核实，工具不能直接覆盖。工具可将它生成且未被修改的旧版总控接续脚本迁移为总控与独立通知两个单元；再次运行保留通知 GUID，不重复添加。生成脚本的元数据用于核对链标识、顺序、消息、地图、条件及同组两个单元的绑定，不是游戏完成记录。不要通过修改元数据声明已经完成，也不要用 UI 的简单消息模板替换统计转发钩子或通知条件；改变接续设计后重新生成并校验。

## 校验与交付

接续工具只处理显式计划，不会替任务设计海域顺序。应用后再运行 `KCPS-FinalizeSortieConfig.ps1`，随后运行同一入口的 `-CheckOnly`；接续工具自身的第二次 `-CheckOnly` 也应无待修改项。

总校验的 `SortieChainCheck` 按精确任务选择器识别同一任务的多个普通海域，并检查两个单元的完整脚本、同组绑定、阶段完整性、消息对应、启动开关及完成判据；`SortieChainProblems` 必须为空。通知缺失、被禁用或受到原生直接触发也属于错误。整条链缺失也应报错；单图、活动海域、演习不因这项普通海域规则改变其执行方式。

若用户明确要求同一任务的多图分别启动，通过 `-SortieChainPolicyPath` 向总校验和出击收尾入口传入本次独立执行声明：`Version=1`，`Policies` 数组中每项包含 `QuestId`、`Mode="Independent"`、精确配置名数组 `Groups` 和非空 `Reason`。该声明只解释指定组为什么不需要顺序链，不豁免错误消息或受管理脚本损坏；不能用它掩盖尚未实现的接续。

当前工具不处理跨文件链、分支链或其他目标计数。此类流程按相应阶段规则另行核对完成证据和消息关联，不声称已经通过本工具的完整链验证。

配置的 `说明` 和总控备注应同步写明启动入口、接续顺序、各图达成条件、安全停止行为，以及中断后应由用户核对进度并从合适阶段恢复。生成和校验配置不等于执行任务；未加载运行时应如实说明验证范围。
