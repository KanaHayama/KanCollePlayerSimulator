# KCPS 远征配置

先读 [公共规则](公共规则.md) 和 [命名规则](命名规则.md)。本流程用于普通远征任务、资源远征以及用户明确安排的多步远征链；具体活动的任务条件和远征需求都必须在本次运行中重新提供，不能从标题或历史安排推断。

## 输入与边界

1. 从当前游戏任务页确认任务 `api_no`、完整标题、频次及完成条件。没有接任务要求的资源远征，应明确将计划的 `tasks` 写为 `[]`。
2. 查询当前远征开放状态和所选舰队。生成链要求舰队当前空闲，不能把已派出的远征算作新步骤。
3. 核实每个远征的舰种、舰船数量、等级、配装及成功条件，选择 KCPS 已有且经过核对的独立远征模板。保留其编成筛选、配装和 `OnCheck` 检查器。
4. 明确各舰队的步骤顺序和每步次数。任务计数必须来自用户提供的实际完成记录；任务进度百分比、正在进行的远征和历史记录都不能直接当成已完成次数。
5. 缺少任务确认、开放状态、完整模板或必要输入时停止生成。结构通过不能代替游戏条件和实际配装的核对。

输入和产物保存到本次明确指定的私人路径。`<SKILL_ROOT>` 表示本 Skill 根目录；使用工作区时，`<WORKSPACE_ROOT>` 表示用户明确选定的位置。脚本在 `scripts/expedition/`。

## 通用计划

计划必须符合 [计划结构](../scripts/expedition/data/expedition-plan.schema.json)。所有数字、任务名和模板名都由本次查证及用户目标决定，不使用内置任务清单。

| 字段 | 含义 |
| --- | --- |
| `version` | 当前结构版本，取 `1` |
| `name` | 最终配置名，遵守频次和中文类型命名规则 |
| `memo` | 已核实的任务条件、来源、日期、舰队安排及使用前提 |
| `missions` | 本次涉及的远征；每项显式填写 `id`、`name`、`minutes`、`unlockStateRequired` |
| `tasks` | 本次需要接取的任务；每项填写 `questNo`、`title`、`priority` 和 `requirements`；每个要求写 `missionId` 与目标 `count` |
| `chains` | 用户选定的舰队与步骤；每项填写 `fleet` 和有序的 `steps`，每步填写 `missionId`、执行 `count`、`templateName` |

同一舰队只声明一条链。`templateName` 精确匹配模板文件中的配置名；该模板的远征 ID、总控舰队和出发舰队必须与步骤一致。工具不会把某个远征的条件检查器换个 ID 后套给另一个远征，也不会猜测如何将舰队专用筛选条件改成另一舰队。

用于推荐的完成记录单独保存在 JSON 文件中，结构为 `completed` 对象：第一层键是任务 `questNo` 的字符串，第二层键是远征 `missionId` 的字符串，值为已完成次数。每项都必须明确填写，包括零；工具不自动初始化、累计或保存完成状态。任意远征计数任务可以由调用方明确选择本次要执行的远征，并将相应目标写入计划；不能据此改写游戏本身的任务条件。

## 查询与推荐

```powershell
$SKILL_ROOT = '<SKILL_ROOT>'
$WORKSPACE_ROOT = '<WORKSPACE_ROOT>'
$env:KCPS_WORKSPACE = $WORKSPACE_ROOT
$tools = Join-Path $SKILL_ROOT 'scripts/expedition'

& (Join-Path $tools 'Get-KCPSExpeditionSnapshot.ps1') -PlanPath '<PLAN_PATH>' -OutputPath '<SNAPSHOT_PATH>' -AsJson
& (Join-Path $tools 'Find-KCPSDefaultExpeditionTemplate.ps1') -DefaultPath '<DEFAULT_CONFIG_PATH>' -AsJson
& (Join-Path $tools 'Get-KCPSNextExpedition.ps1') -PlanPath '<PLAN_PATH>' -StatePath '<STATE_PATH>' -Fleet <FLEET_ID> -SnapshotPath '<SNAPSHOT_PATH>' -AsJson
```

快照工具只查询缓存接口。任务页或远征页缓存不完整时，应先刷新游戏对应页面。未提供 `-OutputPath` 时只返回结果，不保存账号数据。

离线查询使用 `-SourcePath` 指向调用方提供的原始快照，必须含原采集时间 `CapturedAt`、舰队数组 `Fleets`、任务页对象 `QuestList`（包含 `api_list`）和远征页对象 `MissionList`（包含 `api_list_items`）。转换时保留原采集时间，不把旧文件伪装成当前状态。

推荐工具必须明确指定 `-Fleet`，只读取计划、完成记录和快照。它按输入的任务优先级、远征时长及 ID 排序；忙碌舰队返回等待，无法确认开放的远征不作为可派遣候选。`InProgress` 仅供查看，不从任务剩余次数中扣除。候选仍需核对实际编成与配装，推荐结果不直接派遣舰队。

省略推荐工具的 `-SnapshotPath` 时，会按输入计划只读查询当前数据。推荐与生成默认要求快照在 15 分钟内；`-MaxSnapshotAgeMinutes` 可显式调整允许的年龄，但不能代替刷新游戏缓存。

## 生成远征链

模板文件使用 KCPS 原生配置或配置数组。每步模板必须是独立配置，包含唯一的 `RelationalExpeditionWorkflow` 和它关联的 `SimpleExpeditionWorkflow`，可以同时包含编成、改装、补给和入渠执行单元。出发单元必须保留完整的脚本条件检查器。模板文件还需提供可复制的 `MemoWorkflow`、`SeriesByTimerWorkflow`，有任务时需要 `BasicAcceptQuestWorkflow`。

生成器复制步骤的整个执行单元集合，保留编成筛选、配装、检查器及内部关联，然后重新生成 GUID。步骤之间只按照计划顺序建立关联，各舰队第一步由同一启动器触发。所有执行单元均关闭加载时启用和启用时立即触发。

```powershell
& (Join-Path $tools 'New-KCPSExpeditionChain.ps1') -PlanPath '<PLAN_PATH>' -TemplatePath '<TEMPLATE_PATH>' -SnapshotPath '<SNAPSHOT_PATH>' -OutputPath '<CONFIG_PATH>'
```

每一步按输入 `count` 停止，失败不忽略；编成失败不能被当作该步完成。包含其他自动停止条件或自定义总控脚本的模板会被拒绝，需先核实并整理为可独立串联的模板。脚本中写死执行单元 GUID、跨配置关联、重复 GUID 或模板类型不受支持时同样拒绝生成。

链使用总控的自动停止关联推进。运行时不要使用“本轮结束后强制自动停止”一类手动开关，因为它也会触发后续步骤；需要中断时应停止整条链。此工具不把手动强制停止作为远征成功的证明，也不自动提交任务或选择奖励。

## 校验与交付

- 生成器检查输入结构、快照时效、任务 ID 与标题、远征开放状态、模板匹配、唯一 GUID 和内部引用。
- 核对生成文件中每条链的舰队、步骤和次数与输入一致，编成配装和条件检查器完整保留；首项为 `说明`，任务接取失败不能被忽略。
- 人工核对当前舰船、装备占用、成功条件和完整任务详情，再在 KCPS 中确认模板能正常加载。结构校验不能证明任意自定义检查器正确。
- 对外只交付用户要求的配置文件与必要使用说明；账号计划、快照、完成记录和模板来源不写回本 Skill。
